# Event Sourcing в AccountingService

AccountingService хранит все мутации как события в append-only event store,
а не как текущее состояние в CRUD-таблицах. Баланс счёта — проекция,
вычисляемая проигрыванием событий.

Причина: аудитлог — жёсткое бизнес-требование. Event sourcing даёт его
естественно — каждая финансовая операция уже записана как неизменяемое событие.
Компенсирующие операции (возврат AssignFee при реассайне) выполняются через
добавление нового события (Credited), а не через update-in-place.

Альтернатива: классический CRUD — таблицы `accounts` (текущий баланс) +
`transactions` (история). Отвергнута: требует дополнительных механизмов для
гарантии неизменяемости аудитлога и усложняет компенсирующие операции.
