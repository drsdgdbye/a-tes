# JWT Access + Refresh токены

Аутентификация через пару токенов: короткоживущий access-токен (15 минут,
подписан закрытым ключом Auth, проверяется Gateway локально по публичному
ключу) и долгоживущий refresh-токен (7 дней, хранится в Auth DB).

Причина: access-токен проверяется без network call к Auth — Gateway не зависит
от доступности Auth при каждом запросе. Refresh-токен позволяет отзывать
сессии (logout, disable user) без сокращения времени жизни access-токена до
неприемлемо короткого.

Альтернативы:
- Один долгоживущий JWT без refresh — проще, но не поддерживает отзыв сессий.
- Сессионные cookie — требуют хранения сессий в Gateway или вызова Auth
  на каждый запрос, создавая жёсткую синхронную зависимость.
Отвергнуты ради баланса между безопасностью и независимостью сервисов.
