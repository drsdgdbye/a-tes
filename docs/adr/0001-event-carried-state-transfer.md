# Event-Carried State Transfer

События Kafka несут все данные, необходимые потребителю для обработки.
Потребители не делают синхронных HTTP-вызовов к продюсерам за недостающей
информацией.

Причина: синхронные вызовы между сервисами создают coupling по доступности —
если продюсер упал, потребитель не может обработать событие. Дублирование
данных в событиях (например, название задачи в TaskAssigned, TaskCompleted
и PaymentProcessed) — плата за полную независимость сервисов.

Альтернатива: события-уведомления + HTTP-запросы за деталями (тонкие события).
Отвергнута из-за создания скрытых синхронных зависимостей, нарушающих
модель eventual consistency.
